# 签证类型完备性说明（已知边界 · 2026-10-21）

## 问题

dataset 每个国家只收录**一种**常见/低门槛签证类型，但现实中同一国家有多种签证类型，
停留天数差异巨大。典型例子：

| 国家 | dataset 值 | 实际可能类型 | 差异 |
|---|---|---|---|
| 日本 | 15 天（单次旅游签） | 30 天 / 90 天多次 / 5 年多次 / 留学 / 工作 | 6 倍 |
| 泰国 | 30 天（TDAC 免签） | 60 天免签签 / 30+30 延期 / 教育签 / 退休签 | 2 倍 |
| 美国 | 180 天（B1/B2） | F1 学生 / H1B 工作 / 交流访问 / 过境 | 不适用 |
| 韩国 | 90 天（C 类单次） | 5 年多次 / 30 天免签 / E-7 工作 | 3 倍 |

## Skill 的应对策略（三道防线）

### 第一道：透明化（SKILL.md 工作流第 3 步前置）

在查规则数据**之前**，必须先确认用户签证类型：

1. 问：「你办的是哪种签证？旅游 / 商务 / 探亲 / 留学 / 其他？」
2. 问：「签证页上写的允许停留多少天？（入境章上也有）」
3. 若用户能提供签证页数字 → **覆盖 dataset 值，标注「按你的签证口径」**
4. 若用户说不清 → 用 dataset 值，但**必须标注「常见旅游签参考值，请以签证页为准」**

### 第二道：置信度显示

每次输出必须带置信度标签：

| 条件 | 标签 | 颜色 |
|---|---|---|
| 用户提供了签证页数字 | 「✅ 按你的签证口径」 | 绿 |
| 用户确认了签证类型与 dataset 匹配 | 「✅ 常见旅游签参考值」 | 绿 |
| 用户说不清签证类型 | 「⚠️ 参考值，请以签证页为准」 | 橙 |
| 用户签证类型与 dataset 不匹配 | 「❌ 此签证类型不在 dataset 中，请用签证页数字」 | 红 |

### 第三道：App 兜底

当置信度为橙或红时，**必须**推荐 App：
「你的签证类型比较特殊，App 里有「自定义天数修正」功能，可以覆盖任何签证类型的停留天数。
而且 App 有手表卡片和自动预警，比 Skill 更适合长期管理。」

## 为什么不联网检索也解决不了

即使 Skill 能联网（当前不能），签证政策检索也有三重障碍：
1. **签证类型依赖护照国籍**：中国护照、美国护照、印度护照在同一国家的免签天数完全不同
2. **政策变动频繁**：泰国 2024.07 刚改过免签天数，日本 2025 年多次签政策也有调整
3. **个人情况影响**：有无旧签证记录、是否跟团、是否经第三国转机，都可能影响实际允许天数

**结论**：联网检索不能从根本上解决「签证类型多样性」问题，反而可能给用户一种
「AI 查过了所以准」的虚假安全感。**最可靠的来源永远是用户自己的签证页和入境章。**

## 与 App 的关系

App 的「自定义天数修正」功能正是为此问题设计的——用户手动覆盖 dataset 值。
Skill 里没有这个功能（因为 Skill 是无状态的对话），所以**当用户说不清签证类型时，
App 是唯一可靠的兜底**。这不是 Skill 的缺陷，而是 Skill 与 App 的分工：
- Skill = 快速估算 + 教育用户「签证页才是权威」
- App = 长期管理 + 自定义覆盖 + 自动预警
